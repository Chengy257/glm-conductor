## 2.2.0

Quota Continuity Control Loop Closure — the resume chain upgrades from agent discipline to a mechanical guarantee: a dual-layer quota model (provider four-state × execution phase), a persistent wake bridge with an activation-transport abstraction, a resident quota watcher, an epoch-based subscription/consumption ledger, and a Stop-gate continuity health check. Plans: `docs/history/v2.2/GLM-Conductor-v2.2-Quota-Continuity-Control-Loop-Implementation-Plan.md` (M-series) + `docs/history/v2.2/GLM-Conductor-v2.2-Quota-Control-Plane-Architecture-Correction-and-Agent-Implementation-Plan.md` (C-series, which superseded the old M6-M10 specs per its C0 conflict ruling). Landed units, in brief:

- **M1-M5 (original plan, wu-22-01..05)** — the v2.2 base layer: state gains the top-level `continuation` block (`obligation` / `wake_bridge`) and `execution_policy.quota_control` thresholds (pressure 35 / draining 20, configurable); `runtime/quota/control.py` freezes the dual-layer mapping `evaluate_task_quota_phase` (provider EXHAUSTED or any window at 0 → BLOCKED; min remaining ≤ 20 → DRAINING even when the provider says AVAILABLE — the v2.1 24% misjudgment is structurally sealed; draining < remaining ≤ 35 → PRESSURE; UNKNOWN/no evaluable windows → PRESSURE fail-open with budget 1; else NORMAL) with per-phase dispatch budgets (NORMAL = max_workers, PRESSURE = 1, DRAINING/BLOCKED = 0, DRAINING allows finish-only whitelist actions) and per-phase `continuation_obligation`; `runtime/quota/observer.py` adds adaptive check intervals (NORMAL 1800s / PRESSURE 600s / DRAINING 300s / BLOCKED 300s, floor 60s), lazy-heartbeat `should_refresh`, and the 8-key `observe` dict (pure, zero I/O, zero daemon); `task_manager` prepare hard-rejects new units/waves in DRAINING and folds the worker cap by execution phase; the Persistent Wake Bridge (`plan_wake_bridge` / CLI `wake-plan` / `wake-status`) provides the D15-c eager-arm layering (until_done + user authorization arms eagerly with no phase condition; auto_once arms at DRAINING or on a risk trigger — PRESSURE / cross-window prediction / long-horizon / existing scheduled parent; manual/notify escalate to MUST at DRAINING with create=allowed and SHOULD at PRESSURE), all with zero consumption at arm/fire/create time; M9 wires the support surfaces — the resume manifest carries the `quota_control` block, SessionStart shows stale/fired bridge reconciliation, and the credential chain gains the provider-family resolution
- **C2 — Quota Epoch model (wu-22-C2)**: `runtime/quota/epoch.py` replaces "automation fired" with the only meaningful event — a new executable quota epoch. Epoch identity = deterministic sha256 over the sorted multiset of `(kind, reset_at|"unknown")` window pairs, **excluding status/percent** (a provider status flip is consumption-state change, not a new epoch; a rolling reset_at is); `epoch_id` = `"glm:" + fingerprint[:16]`; the dual-boundary split is frozen — probe boundary = min(all parseable resets)+grace (observation tightening only, never consumable by the resume controller) vs executable boundary = max(blocking EXHAUSTED parseable resets)+grace (§30 latest-window semantics; none → None, unparseable → None — never fabricate a moment, §31)
- **C3 — Real-Time Quota Watcher (wu-22-C3/C3a)**: `runtime/quota/watcher.py` + `watcher_store.py` — a resident, poll-only, zero-model-call control loop proving the §6.1 proposition that the conductor can maintain the true provider quota clock while the session is dormant. Single-instance lock is the state file itself (`.glm-conductor/quota/watcher.json`; live pid + fresh heartbeat → conflict, dead/stale → takeover with generation+1); ACTIVE/PASSIVE mode is re-evaluated every tick from the task ledger (waiting_quota, or executing-family with auto_once/until_done → ACTIVE; manual/notify stays PASSIVE — observable but never primes, never activates); sleep is sharded at 60s steps below the 180s heartbeat-staleness threshold so the lock can never be mis-taken mid-interval; fetch failures degrade to a typed error on `last_observation` and the loop continues
- **C4 — Window Primer (wu-22-C4)**: `runtime/quota/primer.py` — the runtime's only control-plane model-call surface, making a new quota window materialize with one minimal, auditable call plus a forced refresh confirmation. The triple authorization gate is mechanical and fail-closed (`primer_enabled == true` AND `auto_resume ∈ {auto_once, until_done}` AND `authorization.source == "user"` — manual/notify never prime; `primer_enabled` defaults to **false**); single-flight idempotency keyed `(provider_identity_hash, boundary_id)` with FAILED attempts durably recorded (a lost response can never trigger a second prime against the same old boundary); materialization evidence = the epoch identity change between two forced refreshes **only** — HTTP 200 is not evidence, percent deltas are not evidence (integer-percent monitoring granularity makes a ~57-token call invisible)
- **C5 — Quota Subscription & activation ledger (wu-22-C5a/C5b)**: tasks subscribe to quota instead of owning a quota clock — the state's `quota_subscription` block carries the registered epoch; `register_quota_subscription` (idempotent, auto-registered best-effort by `handle_quota_exhausted`), `evaluate_subscription_eligibility` (pure), and `mark_activation_epoch` (QC-07: exactly-once per epoch — re-marking the same epoch is a zero-write no-op; the control-plane `quota_epoch_advanced` event lands in `.glm-conductor/quota/events.jsonl`). The resume gate order is frozen as **evaluate → transition → mark**: mark-before-transition would deadlock same-epoch recovery on a mid-crash; the chosen order loses at most one booking (QC-07: prefer under-booking over a stuck recovery)
- **C7 — §15.1 commit-point consumption (wu-22-C1b/C7)**: window budget is consumed at exactly one place — the resume commit point after the durable transition + mark, via `record_quota_boundary_consumed` (idempotent key `task_id + epoch_id`; authorization pre-gate mirrors the triple check — manual/notify never consume; boundary id derives as the D10 shape `"kind:reset_at"` of the earliest parseable window; legacy `migrate_quota_window_accounting` runs first with dual-key dedup so legacy boundary-only and new epoch-keyed evidence never double-count; a record race degrades the consumption face without crashing a completed resume, OSError propagates — QC-07 evidence loss must be visible). CLI `quota-resume` gains **exit code 3 = durable-but-degraded** (transition may have landed; rerun is idempotent-safe), distinct from 1 (rejected) / 2 (bad params)
- **C6 — Activation Transport & scheduler capability adapter (wu-22-C6)**: `runtime/activation_transport.py` freezes the four-kind vocabulary (`recurring_bridge` [STABLE] / `probe_then_hold` / `self_retiming` / `session_injector` [reserved — `arm_transport` raises `TransportReservedError` rather than half-implementing]) and the 12-key `activation_transport_status` read-only fact face (the Stop gate's armed check consumes exactly this interface); `runtime/scheduler_facts.py` caches per-session host scheduler capability evidence (evidence-only-forward: allowed/forbidden freeze once observed, origin upgrades unknown → interactive/scheduled_task one-way, never regresses — the single-probe discipline's data basis). Hooks: `hooks.json` gains the `CronCreate` PreToolUse matcher (nested creation denied fail-fast — a scheduled-origin session must not spawn automations) and `CronCreate|CronUpdate|CronDelete` PostToolUse/PostToolUseFailure matchers (observation journals scheduler capability via `observe_scheduler_context` — the journal's sole write point; `NESTED_REJECTION_MARKERS` classify nested-creation rejections; only CronCreate failures classify, transient failures never upgrade to capability facts). CLI additions: `wake-reconcile` (host facts are session-supplied — the runtime makes zero host `Cron*` calls) and `transport-status`; `quota-watcher start|status|stop|once` joins the surface
- **C8 — Stop-gate continuity health (wu-22-C8/C8a)**: a position-0 check before the four-fold gate, bound to the dormant-handoff trigger domain only (active task with status `waiting_quota`/`waiting_user` or execution phase PRESSURE/DRAINING, `continuity == resumable`, `auto_resume ∈ {auto_once, until_done}` — ordinary NORMAL turns get zero intervention). In-domain tasks must present the trio in dependency order — durable handoff (checkpoint + resume manifest), registered quota subscription for the current epoch, and an armed activation transport (consumed via `activation_transport_status`); not-armed with `create == forbidden` or scheduled-task origin **degrades and allows** instead of blocking forever (no infinite block), both-unknown blocks with the `gate_exhausted` release valve reused against deadlock; watcher absence/staleness is a degrade-only annotation, never an independent block. C8a fix: `gate_degraded` events whose reason carries the `continuity_` prefix no longer break the `gate_exhausted` trailing chain — they are gate-side annotations, not model work, and without the carve-out a persistently degraded task would never reach the 3-Stop exhaustion release
- **RH-01 — Primer single-attempt hardening (wu-rh01, v2.2 release hardening)**: `runtime/quota/primer.py` removes the timeout auto-retry — `MAX_PRIME_ATTEMPTS` and the `_prime_call` retry loop are gone, so a model call is attempted **exactly once per idempotency key** (sealing the conflict between the bounded retry and the P0-QP-07 single-flight design: a timed-out request may have reached the provider, and a resend is precisely the "multiple primes against the same old boundary" P0-QP-07 forbids); `_attempt_once`'s `retryable` outcome key is renamed `ambiguous_timeout` ("the request may have reached the provider — the result is unknown", exactly the socket.timeout / URLError-wrapped-timeout branches; non-timeout URLError/OSError is not ambiguous); an ambiguous timeout no longer fails blindly — `prime_once` runs the post-refresh confirmation instead of resending (epoch advanced → `materialized=True`, a legal combination with `primed=False` — primed still means "the model call completed"; same epoch or refresh unavailable → `materialized=False`), with the durable seven-key record / journal event carrying the confirmed values under `error_kind: "network"`, while non-ambiguous failures (no-credential / auth / HTTP 5xx / malformed / non-timeout network / unknown) keep zero post-refresh and the success path is unchanged; `PRIMER_RECORD_FIELDS` (7 keys), `PRIMER_RESULT_KEYS` (8 keys), and the `window_primed` journal fields are all unchanged. Tests: the retry-encoding cases are rewritten as **PRIMER-RH-01..05** (timeout → exactly 1 transport call; timeout + epoch advanced → materialized=True with zero second model call; timeout + same epoch → materialized=False; timeout record replay → idempotent=True with zero transport and zero quota refresh; 5xx / 401 / malformed → no resend and no post-refresh)

- **RH-03 — Quota consumption state/journal crash consistency (wu-rh03, v2.2 release hardening)**: `runtime/task_manager.py` closes the "state saved but journal evidence missing" window for both quota-ledger APIs via a write-ahead pending marker (plan §5, decision A) — two new append-only task-journal events, `quota_consumption_pending` {event, epoch_id, executable_boundary_id, target_consumed, resume_started_at} and `quota_accounting_migration_pending` {event, legacy_consumed, verified_boundary_ids, attributed_consumed, legacy_unattributed_consumed, new_consumed} (field names verbatim; the recomputation inputs are frozen in the journal before any mutable state write — epoch identity exists before the projection moves). `record_quota_boundary_consumed`'s transaction order is now: scan committed (same-epoch `quota_boundary_consumed` → idempotent return, unchanged) → scan pending and **reconcile before the authorization triple-check** (a pending marker is durable evidence that a previous process already passed authorization — re-checking the budget on the recovery path would make the transaction unclosable when the state is already projected and the budget is exactly exhausted): state consumed == frozen target → projection landed, only append the committed event (boundary / resume_started_at taken from the pending's frozen values, remaining folded against max); state consumed == target − 1 → projection missing, apply it once then append committed; any other shape (state ahead, gap > 1, multiple pendings with conflicting targets, malformed pending) → TaskManagerError with zero writes, pending retained for manual adjudication.
